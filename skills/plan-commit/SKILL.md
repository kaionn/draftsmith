# /plan-commit — plan ファイルの畳み込みコミット

plan ファイル（/draftsmith が書き出した一時設計文書）の内容を「subject 一行 +
body に設計文書」の形でコミットメッセージへ畳み込み、コミット成功後に plan
ファイルを削除する。設計意図の永続化先をファイルから **git 履歴**に移すのが目的。

## スコープ

- 行うのは「1 つの plan ファイル → 1 コミット」の畳み込みだけ
- **push・PR 作成・タグ作成はしない**
- plan ファイル以外の判断（何を stage するか）は必ず人間に見せてから進める
- repo ルートの `Plans.md`（タスク台帳）には触れない。cc: マーカーの更新は
  harness-sync 等の領分

## Step 1: 対象 plan ファイルの特定

- 引数にパスがあればそれを使う
- なければ repo ルートの `plans/*.md` から、冒頭に一時設計文書の警告引用ブロック
  （`> ⚠ 一時設計文書` で始まる）を持つファイルを列挙する
  - 1 件 → それを対象にする
  - 複数 → AskUserQuestion で選んでもらう
  - 0 件 → 「畳み込める plan ファイルがない」と報告して終了
- 対象ファイルを Read し、`Status:` を確認する。`designed` のまま（実装未完の疑い）
  なら、その旨を警告してから続けるか確認する

## Step 2: コミット対象の確認

`git status --porcelain` と `git diff --stat`（+ `--cached`）で現状を把握する:

- staged 変更があればそれをコミット対象とする
- staged が空で working tree に変更があれば、対象ファイル一覧を提示して
  「これらを stage してよいか」を確認してから `git add`（**個別パス指定**。
  `git add -A` は使わない。plan ファイル自身と無関係ファイルを混ぜない）
- どちらも空なら「コミットする変更がない」と報告して終了

## Step 3: コミットメッセージの組み立て

- **subject**: plan の `# Plan: {タスク名}` から一行で作る（日本語・変更の要旨）
- **body**: plan ファイル本文から以下を除いたもの:
  - 冒頭の警告引用ブロック（`> ⚠ ...` の 2 行）
  - メタ行のうち `Lane:` / `Status:`（`Source:` は残す。台帳タスクとの
    トレーサビリティになるため）
  - 未転記のプレースホルダ（「（実装完了時に転記）」等）が残る節
- リポジトリ既定のコミットフッター規約（Co-Authored-By 等）があれば従う

## Step 4: プレビュー承認 → コミット → plan 削除

1. 組み立てたコミットメッセージ全文と stage 済みファイル一覧を提示し、
   **人間の承認を得る**（承認なしのコミットはこのスキルでは禁止。
   自律モードや「！」指示でも省略しない）
2. 承認後 `git commit` を実行し、成功を確認する
3. コミット成功後に plan ファイルを `rm` で削除する（内容はコミット履歴に
   移っているため安全。untracked なので git への影響はない）
4. 一行で報告する: コミット hash / subject / 削除した plan ファイル名

## トラブル時の原則

- commit が pre-commit hook 等で失敗したら、plan ファイルを**削除せず**に
  失敗内容を報告する（畳み込み前の削除は設計文書の喪失になる）
- メッセージ承認で修正指示を受けたら、組み立て直して再提示する（2 往復まで。
  それ以上は方針をユーザーに確認する）
